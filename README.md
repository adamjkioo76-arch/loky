# LUMORA

تطبيق عربي لإدارة الأموال الشخصية. الواجهة تستخدم React وVite، وتُخزَّن البيانات في Supabase/PostgreSQL. المبالغ المالية محفوظة بوحدات العملة الصغرى كأعداد صحيحة (`bigint`)، ولا توجد بيانات مالية تجريبية.

## المتطلبات

- Node.js LTS وnpm.
- مشروع Supabase.
- لا يحتاج تشغيل الواجهة إلى أسرار خادمية؛ يستخدم مفتاح Supabase `anon` العام فقط.
- ملف `.env.example` مخصص فقط لأسرار Edge Function الاختيارية، ولا تقرأه واجهة Vite.

## التشغيل المحلي

```powershell
npm install
npm run dev
```

أوامر التحقق:

```powershell
npm test
npm run test:e2e
npm run build
```

يتطلب اختبار Playwright تثبيت Chromium مرة واحدة باستخدام `npx playwright install chromium`.

## إعداد Supabase

1. أنشئ مشروعاً في Supabase.
2. انسخ رابط المشروع ومفتاح `anon` العام من إعدادات API إلى `config.js`. القيم في الملف فارغة عمداً. لا تستخدم مفتاح `service_role` في المتصفح مطلقاً.
3. نفّذ ملف `supabase/migrations/202611120001_initial_schema.sql` مرة واحدة من SQL Editor في لوحة Supabase. ينشئ الجداول والقيود والفهارس وRLS وسياسات الملكية والإجراءات الذرّية. يُنشأ الملف الشخصي والحساب الرئيسي والتصنيفات الافتراضية عند إنشاء مستخدم جديد.
4. فعّل تأكيد البريد الإلكتروني في Authentication، وأضف عنوان التطبيق المحلي وعنوان النشر إلى قائمة Redirect URLs المسموح بها. صفحة تغيير كلمة المرور لا تعمل إلا من جلسة رابط الاستعادة.
5. ابدأ التطبيق وسجّل مستخدماً جديداً. لا يظهر Dashboard إلا بعد تسجيل الدخول.

## الوظائف الحالية

- التسجيل والدخول واستعادة وتغيير كلمة المرور عبر Supabase Auth.
- لوحة عربية RTL تستمد الأرصدة والمعاملات من قاعدة البيانات وتعرض حالات التحميل والفراغ والخطأ.
- إنشاء وتعديل وحذف الدخل والمصروفات والإيداعات والسحوبات، والتصنيفات المخصصة والبحث.
- حسابات متعددة وأرشفة الحساب، وتحويل داخلي ذري بين الحسابات بمفتاح منع تكرار وفحص للرصيد.
- ميزانيات أسبوعية وشهرية ومخصصة، وتصنيف اختياري وتنبيهات عند الحدود المحددة.
- أهداف ادخار وتقدمها وحساب تقدير الادخار الشهري.
- إعدادات العملة والمظهر والراتب، تسجيل دورة راتب مؤكدة وإيداع فائضها إلى حساب ادخار عند تفعيل الإعداد.
- مركز إشعارات، تقارير فعلية وتصدير CSV، وإعادة تعيين مالية محمية ومسجلة في سجل التدقيق.
- واجهة المساعد المالي اختيارية؛ لا تُنشأ إجابات أو أرقام وهمية عندما لا تكون Edge Function مهيأة.

## الأمان وحدود التكامل

- RLS مفعّل على كل الجداول الخاصة بالمستخدم، والإجراءات المالية الحساسة تتحقق من هوية المستخدم داخل PostgreSQL.
- لا يمكن إدراج أو تعديل أو حذف طرف واحد من تحويل داخلي من الواجهة؛ يُنفّذ التحويل في RPC واحد مع أقفال على الحسابات.
- يمنع التحقق في قاعدة البيانات من تسجيل مصروف أو تحويل أكبر من الرصيد المتاح.
- صفحة الإعدادات لا تحذف حساب Auth عند إعادة تعيين البيانات المالية.
- يظل تكامل Gemini غير نشط حتى تنشر Edge Function `lumora-ai` وتضبط أسرارها (`GEMINI_API_KEY` و`APP_ORIGIN`)؛ قيمة `SUPABASE_ANON_KEY` فقط تُستخدم للتحقق من المستخدم وقراءة بياناته وفق RLS. وظيفة الذكاء الاصطناعي ترسل ملخصاً مجمعاً لآخر 30 يوماً والتصنيفات إلى Google Gemini بعد موافقة المستخدم في الواجهة، ولا ترسل أوصاف المعاملات.
- تصدير PDF وربط الخدمات المالية الخارجية غير مفعّلين.
- لا توجد PWA أو مزامنة بنكية أو محافظ خارجية في هذه النسخة.

## البناء والنشر

```powershell
npm run build
npm run preview
```

انشر محتوى `dist/` على استضافة تدعم تطبيقات Vite الثابتة، وأضف عنوان النشر إلى Redirect URLs في Supabase. أعد بناء التطبيق بعد إضافة إعدادات Supabase في `config.js`. لا تضع مفاتيح خاصة في ملفات الواجهة أو ملفات ZIP.

## الاختبارات

- اختبارات Vitest للحسابات المالية بوحدات العملة الصغرى.
- اختبارات Playwright للتنقل الأساسي بين شاشات المصادقة.
- اختبارات صلاحيات RLS وعمليات PostgreSQL تحتاج مشروع Supabase مهيأً؛ لا تعتبر ناجحة دون تنفيذها على مشروع اختبار منفصل.

لنشر المساعد اختيارياً، ثبّت Supabase CLI، ثم أضف أسرار `GEMINI_API_KEY` و`APP_ORIGIN` من طرفية آمنة، وانشر `supabase/functions/lumora-ai`. لا تضع مفتاح Gemini في `config.js` أو الواجهة.
